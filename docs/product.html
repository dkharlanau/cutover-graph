Cutover Graph

Replace the cutover spreadsheet's implicit dependencies with a live, versionable graph that knows what can execute now, what is blocked, which checkpoint is missing, how delays propagate, and when a contingency branch should activate.

A task marked “done” is not dependency-complete if its required checkpoint evidence or approval is still missing.

Why it exists

Cutover calls become difficult when the plan, live status, timing, evidence, and rollback logic are all represented differently. The graph keeps those constraints in one model that can be recalculated as the window moves.

01

Know what can run now

Dependency completion, checkpoints, statuses, and active contingencies determine executable work instead of a manually colored status column.

02

See timing consequences

Critical path and timezone-aware forecasting distinguish an originating delay from delay inherited through dependencies.

03

Make fallback explicit

Rollback and contingency are separate conditional DAGs with their own dependencies, blockers, waves, and completion state.

A control-room model, not a static plan

The same graph supports planning before the window and live readiness questions during execution. The published synthetic case is generated from repository examples and is also available as JSON and Markdown.

Typical operating loop

python -m pip install .
cutover-graph validate examples/customer-cutover.json
cutover-graph plan examples/customer-cutover.json
cutover-graph gate examples/customer-cutover.json \
  examples/readiness-policy.json
cutover-graph timing examples/timed-cutover-before.json
cutover-graph diff examples/timed-cutover-before.json \
  examples/timed-cutover-after.json

Decisions retain rationale

Checkpoints attach approvals and evidence to concrete tasks. Readiness policy can require owners, satisfied checkpoints, completed prerequisites, and blocker limits before go-live proceeds.

Not a scheduler that blindly executes production commands. The current core models, evaluates, forecasts, and gates cutover state; controlled command hooks belong behind explicit approval envelopes.

Where it connects

Cutover is where multiple forms of assurance converge. Reconciliation and evidence should become dependencies, not links pasted into a status cell.

Agent entry point

An agent can coordinate state without becoming the approver.

The manifest exposes validation, planning, timing, diff, contingency, and gating. Agents can surface blockers and executable tasks; required approvals and evidence remain explicit human/governance inputs.
